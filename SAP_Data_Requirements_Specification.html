SAP Data Requirements Specification

SmartStock LiveRetail — Real-Time Replenishment Engine

Document Version: 1.2 (Updated per S/4HANA Technical Data Requirements Runbook — SmartStock LiveRetail Replenishment Matrix V1.2) Prepared For: Client SAP BASIS / Integration Team Purpose: This document defines every SAP object, entity set, and field that the SmartStock platform requires read or write access to. It is intended to be handed to the SAP team to set up the OData Gateway configuration, user authorizations, and field-level access.

Overview

SmartStock communicates with SAP S/4HANA via standard OData V2 services exposed through the SAP API Gateway. All integration is stateless and REST-based. There are two directions of data flow:

DirectionData FeedSync ScheduleMechanism
SAP → SmartStock (INBOUND)Purchasing Info RecordsWeeklyHTTP GET via OData V2
SAP → SmartStock (INBOUND)Transit Pipelines / Open POsEvery 15 minutes (delta sweep)HTTP GET via OData V2
SAP → SmartStock (INBOUND)Inventory Stock BaselineNightly at 02:00HTTP GET via OData V2
SmartStock → SAP (OUTBOUND)Scrap Write-Back + PO CreationEnd-of-day aggregated batchHTTP POST $batch via OData V2
⚠️ Important: All outbound write-backs are aggregated and batched — they are never made in real time per transaction. This minimises SAP Digital Access licensing costs by collapsing thousands of individual events into a single daily document per store.

PART 1 — INBOUND DATA (SAP → SmartStock)

1.1 — Purchasing Info Records (Pricing, MOQ & Lead Times)

Business Purpose: Provides unit price, minimum order quantity, and vendor lead time for each SKU. Used to generate financially-validated replenishment recommendations and calculate purchase order values. SAP OData Service: APIINFORECORD_PROCESSSRV Entity Set: A_PurInfoRecPlantData HTTP Method: GET Response Format: application/json Sync Schedule: Weekly loop — full refresh of all purchasing constraints Trigger: Scheduled weekly pull via sap-extractor Edge Function Endpoint Pattern: 

GET {SAP_GATEWAY_BASE_URL}/sap/opu/odata/sap/API_INFORECORD_PROCESS_SRV/A_PurInfoRecPlantData
    ?$format=json
    &$select=Material,MaterialGroup,Supplier,NetPrice,MinimumOrderQuantity,PlannedDeliveryDurationInDays
    &sap-client={SAP_CLIENT_ID}

1.2 — Open Purchase Orders (In-Transit Stock)

Business Purpose: Identifies which SKUs already have open inbound deliveries from vendors. This prevents duplicate replenishment orders for stock already on its way. SAP OData Service: APIPURCHASEORDER_PROCESSSRV Entity Set: A_PurchaseOrderItem HTTP Method: GET Response Format: application/json Filter: $filter=OrderQuantity gt ReceivedQuantity and MandatoryPrcmtDocIsDeleted eq false Sync Schedule: 15-minute delta sweep — continuous in-transit quantity refresh Trigger: Scheduled delta sweep via sap-extractor Edge Function Endpoint Pattern: 

GET {SAP_GATEWAY_BASE_URL}/sap/opu/odata/sap/API_PURCHASEORDER_PROCESS_SRV/A_PurchaseOrderItem
    ?$format=json
    &$filter=OrderQuantity gt ReceivedQuantity and MandatoryPrcmtDocIsDeleted eq false
    &sap-client={SAP_CLIENT_ID}
📝 Note: The filter OrderQuantity gt ReceivedQuantity identifies lines where delivery is still open (not fully received). MandatoryPrcmtDocIsDeleted eq false excludes soft-deleted PO lines, ensuring only active transit pipelines are tracked.

PART 2 — OUTBOUND DATA (SmartStock → SAP)

2.1 — Floor Scrap / Goods Issue Write-Back (Movement Type 551)

Business Purpose: Posts aggregated in-store scrap records (spoiled, damaged, expired goods) to SAP Inventory Management as Goods Issues. These are buffered intraday and posted as a single consolidated batch document at end-of-day to minimise SAP Digital Access licensing charges. SAP OData Service: APIMATERIAL_DOCUMENTSRV Service Path: /sap/opu/odata/sap/APIMATERIAL_DOCUMENTSRV/A_MaterialDocumentHeader Entity Set: A_MaterialDocumentHeader + A_MaterialDocumentItem HTTP Method: POST using multi-part atomic $batch packaging (eliminates indirect system licensing overhead) SAP Movement Type: 551 (Scrapping from unrestricted stock) Trigger: Daily scheduled run via sap-batch-sync Edge Function Outbound JSON Payload Structure (per batch item): 
{
  "GoodsMovementType": "551",
  "Plant": "1001",
  "StorageLocation": "0001",
  "Material": "MAT-FMCG-001",
  "EntryQuantity": 12,
  "EntryUnit": "PC"
}

PART 3 — POS Event Inbound Stream

Business Purpose: The POS system posts a real-time event for every completed customer checkout. SmartStock ingests these to maintain a live, second-accurate stock deduction count intraday (between SAP overnight syncs).
📝 Note: This data comes from the POS system (not SAP). However, it must be aligned with SAP Material Numbers and Plant Codes so deductions correctly map to the SAP ledger.
Integration Mechanism: HTTP POST webhook → Supabase Edge Function Target Table: possalesevents triggers update to liveinventoryledger Expected POS Payload Schema: 
{
  "store_code": "1001",
  "storage_location": "0001",
  "items": [
    { "sku": "MAT-00918", "quantity": 3 },
    { "sku": "MAT-20349", "quantity": 1 }
  ]
}
